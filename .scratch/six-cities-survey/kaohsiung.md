# 高雄市檢舉網站調查

## 網站基本資訊

- 網址：`https://policemail.kcg.gov.tw/Mail.aspx?s=vcVQ6srNJSVOy9ybh4WCkw%3d%3d`（`s` 為一次性 session token，需先在前置頁面完成分類選擇才能取得）
- 分頁標題：「高雄市政府警察局警政信箱-意見信箱」
- **這確實是一個專門的交通違規檢舉表單**，不是通用陳情信箱誤判。頁面內 `<h2>` 明確標示「寫信給我們-交通違規檢舉」，且欄位結構高度結構化（違規類別/子項下拉、地點含行政區下拉、車牌拆兩段、違規日期時間、車種、附件上傳），與臺南、桃園等其他縣市的檢舉表單同一量級。
- 頁面本身是「警政信箱」平台的其中一種郵件類型（該平台同時承載其他一般陳情信箱），但透過此 URL 進入的實例已鎖定「交通違規檢舉」類別。
- 頂部有 5 步驟導引：選擇報案類別 → 交通違規聲明 → **資料填寫（目前所在頁面）** → 收取驗證信 → 完成。也就是說要到達這裡，必須先在前置頁面選擇「交通違規檢舉」分類並勾選/確認過聲明條款——本次是在使用者既有分頁上直接檢視，未重新走過這兩步。

## 身分驗證閘門

- **填寫欄位前不需要登入或先行驗證**：所有違規相關欄位（含車牌、地點、日期時間、違規類別、附件）在本頁面上都可以直接看到並互動，沒有擋在前面的登入牆或模糊遮罩。
- 「驗證」發生在**送出表單之後**：流程步驟第 4 步是「收取驗證信」，也就是送出後系統會寄驗證信到填寫的 EMail，需點擊信中連結才會正式送件（頁面上方也有「重寄驗證信」「進度查詢」連結佐證此機制）。
- 表單要求填寫姓名、身分證字號、居住地址、性別、EMail、電話等真實身分欄位（必填），但這些屬於檢舉人個資，不是「擋住違規欄位」的認證關卡，只是同一頁表單的一部分。
- 送出前需通過圖形驗證碼（CAPTCHA，`id=ContentPlaceHolder1_txtCode`，圖片來源 `Common/DisplayCaptcha.ashx`，另有「語音播放」及「重新產生」）。
- 本次調查全程未輸入任何真實或假造個資，僅操作違規類別下拉、日期時間選擇器、附件 DOM 結構等非個資欄位以確認元件行為。

## 逐欄調查

### date / time
- **合併為單一欄位**：「違規日期/時間」對應單一 `<input id="ContentPlaceHolder1_ViolationDate" class="Wdate">`（`name=ctl00$ContentPlaceHolder1$ViolationDate`）。
- **kind = custom（但底層可 plain 賦值繞過，2026-08-24 已實測確認）**：點擊後彈出的是 [air-datepicker](https://air-datepicker.com/)（DOM class 為 `datepicker--...`，非傳統 My97 `WdatePicker`，`Wdate` 只是殘留的 CSS class 命名），包含月曆格 + 時/分兩條 range slider（預設值取當下時間，例如 `09:46`）。**用 chrome-devtools-mcp 直接對 input 賦值 `'2026-08-01 13:45'` 並 dispatch input/change/blur 事件，值穩定寫入、未被攔截清空、也未觸發驗證錯誤樣式，air-datepicker 彈窗本身（一直存在於 DOM 但 `opacity:0` 且定位在畫面外的 idle 狀態）未被意外喚出。** 因此可比照桃園，直接歸類為 `plain`，不需要新的 iframe/滑桿式 custom 互動模組——落差 4（custom 元件技術不相容）至此兩都皆已解除，剩下的純粹是落差 3（date/time 合併成單一 DOM 元素）的資料流模型問題，且解法只需組出正確格式字串後單純賦值，不必模擬複雜 widget 互動，複雜度比原先預期低。
- **格式為西元（非民國年）**：實測點選 8/15 後，輸入框值變為 `2026-08-15 09:46`（`YYYY-MM-DD HH:mm`），月曆標題也顯示「八月, 2026」而非民國年。
- 日期與時間**綁在同一顆元件同一次選擇裡完成**，不是分開兩個欄位（不像部分縣市把日期、時、分拆成三個 select）。
- 欄位旁提示：「檢舉日期距違規終了日期逾 7 日之交通違規檢舉案件，不予舉發」，需注意日期需落在 7 天內。

### plate
- **kind = plain，但拆成兩個文字輸入框**：`id="ContentPlaceHolder1_LicenseNo"`（title=「車牌號碼(減號前英數字)」）與 `id="ContentPlaceHolder1_LicenseNo2"`（title=「車牌號碼(減號後英數字)」），中間以靜態文字 `-` 分隔顯示。
- 需要程式邏輯將完整車牌以 `-` 拆分後分別填入兩個 input，而非單一欄位直接賦值。
- 表單提示「一次限填寫一個車牌號碼」——不支援多車牌批次檢舉。

### location
- **交通違規地點分成兩部分**：
  - 行政區：`<select id="ContentPlaceHolder1_uscPlace_ddlArea">`（**kind = select**，39 個選項＝高雄市 38 個行政區 + 預設「請選擇」，前面固定顯示靜態文字「高雄市」）。
  - 詳細地址：`<input type="text" id="ContentPlaceHolder1_uscPlace_txtAddress">`（**kind = plain**，寬度 380px），另有隱藏欄位 `uscPlace_txtLng`／`uscPlace_txtLat`／`uscPlace_txtArea`，推測是搭配地圖/地址自動完成 API 使用，但未實測輸入觸發下拉建議（避免產生非必要的外部 API 呼叫），純文字直接賦值應仍可用。
- **role 對應**：
  - `district`（行政區）→ 對應 `uscPlace_ddlArea` 這顆 select，可用程式選項比對。
  - `road` / `remainder` → **無法可靠拆分**。表單只給一個自由文字欄位承載「詳細地址或路口名稱」，官方提示要求填「○○路○○號前(對面)」「○○路與○○路路口」或「無明確地址時填路段名＋方向＋鄰近路口/公里數/地標」等多種格式並存，語意上無法用固定規則穩定拆出「路名」與「其餘片段」，應整段視為 `remainder`（或整段塞進單一自由文字欄位）處理。
- 另有一個**易混淆的第三個下拉**：「違規行政區」`<select id="ContentPlaceHolder1_ViolationArea">`（41 個選項，含「三民一分局」「三民二分局」+ 38 行政區），提示文字說明這是給知道轄區分局的人選填以加速分案，語意上是「轄區/分局」而非地址本身的一部分，不屬於 `location` 的 district/road/remainder 三種 role，需視為獨立的可選欄位。

### description
- **kind = plain（多行）**：`<textarea>` 對應「內容」欄位（accessibility role 顯示為 `textbox ... multiline`），自由文字輸入，無特殊互動元件。

### violation
- **kind = select，且為連動下拉（cascading）**：
  1. 第一層「違規事實」大類：`<select id="ContentPlaceHolder1_ddlViolationEventCategory">`，19 個選項，皆為條號分類（如「不當駕駛行為(闖紅燈)(第53條、第53條之1)」）。此 select 的 `onchange` 直接寫死 `setTimeout('__doPostBack(...)', 0)`，代表選擇後會觸發 ASP.NET 局部回傳（partial postback）。
  2. 第二層具體條文：`<select id="ContentPlaceHolder1_TitleDropDownList">`。初始只有 1 個「請選擇」預設選項；**經實測**選擇第一層「不當駕駛行為(闖紅燈)」後，此下拉會透過回傳被動態填入該類別對應的細項，例如：
     - 「汽車駕駛人，行經有燈光號誌管制之交岔路口闖紅燈。(53.1)」
     - 「汽車駕駛人，行經有燈光號誌管制之交岔路口紅燈右轉行為。(53.2)」
     - 「汽車駕駛人，行經有燈光號誌管制之大眾捷運系統車輛共用通行交岔路口闖紅燈。(53-1.1)」
     - 「汽車駕駛人，行經有燈光號誌管制之大眾捷運系統車輛共用通行交岔路口紅燈右轉。(53-1.2)」
  - **連動關係確認**：欄位 A（大類）未選擇時，欄位 B（細項）只有「請選擇」一個空選項；選了 A 之後 B 才會出現該類別實際可選的細項列表。
- **條文內容具體度**：細項文字包含明確法條號＋子款代號（如 `53.1`、`53-1.2`）與完整白話違規描述，具體度足夠支援程式做文字/模糊比對。

### evidenceImages
- **kind = file，但需搭配「上傳」按鈕分段送出**：
  - 主要作用中的欄位是 `<input type="file" id="ContentPlaceHolder1_fl_File" multiple>`（原生、支援一次多選，`accept` 屬性未限制）。
  - DOM 中還存在 `upload1`/`upload2`/`upload3` 三個舊式 `<input type=file>`，但其父容器皆為 `display:none`，判斷為舊版/停用中的遺留欄位，目前實際生效的只有 `fl_File`。
  - 選擇檔案後，需再按下獨立的「上傳」按鈕（`<input type="submit" id="ContentPlaceHolder1_btnMailFile" value="上傳">`）才會把選取的檔案送出並累加進附件清單（頁面顯示「目前已上傳 0 個檔案，總大小：0 KB」的計數器），這是一個**與主表單「送出」分開的中間回傳步驟**，不是選完檔案就自動含在最終送出時一併提交。
  - 檔案限制：60MB；允許副檔名含文書檔（doc/docx/xls/xlsx/pdf）、圖片（jpg/jpeg/png/bmp/gif）、影音（avi/mp4/mov/wmv）、壓縮檔（rar/zip）。

## 附件上傳機制

（同上「evidenceImages」小節）核心模式是「原生 `<input type=file multiple>` 選檔 → 按『上傳』按鈕觸發回傳附加 → 附件清單計數更新」，不是選檔即自動併入最終送出，也不是逐一彈窗增量注入 DOM 節點的模式。

## 檢舉條文內容

違規大類（19 種）+ 條文細項（依大類動態載入，每類約數項到十餘項不等，本次僅實測「闖紅燈」類別的 4 個細項）皆附完整法條號與白話描述，文字具體、可用於程式比對或模糊比對，品質良好。

## 無法確定 / 需要人工複核的項目

- 除「闖紅燈(第53條/53-1條)」外，其餘 18 個違規大類各自連動出的細項清單內容未逐一實測，需要時應個別觸發 `ddlViolationEventCategory` 各選項並讀取 `TitleDropDownList` 內容以取得完整條文清單。
- 「交通違規地點」自由文字欄位背後綁定的 `txtLng`/`txtLat`/`txtArea` 隱藏欄位，推測用於地址自動完成/地圖定位，但未實際測試輸入行為是否會跳出建議下拉、是否會覆蓋/校驗使用者手動輸入的文字（避免呼叫外部地圖服務或留下測試痕跡），若要精確自動化填寫，建議之後再針對此行為單獨驗證。
- 附件「60MB」限制究竟是單檔上限或全部附件加總上限，頁面文案未明確區分，未實測超量情境。
- 未實測送出後的驗證信與「進度查詢」流程細節（依安全鐵律未觸發真實送出）。
