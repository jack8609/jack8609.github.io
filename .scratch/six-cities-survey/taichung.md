# 臺中市檢舉網站調查

## 網站基本資訊

- 網址：`https://tvrweb.police.taichung.gov.tw/#/wCase`
- 標題：「案件填寫｜臺中-民眾檢舉網站」（臺中市政府警察局 交通違規便民服務網）
- 是否需要登入/驗證：**不需要**。URL 不含任何驗證 token（對照桃園分頁 URL 帶有 `verifyEmail`/`verifyId`/`verityCode` 等參數，臺中沒有），且此頁面本身同時包含「檢舉人資料」與「違規資料」兩大區塊，中間沒有任何 email 驗證關卡或分頁跳轉。
- 頁面整體使用 Vuetify 2（偵測到 `.v-application`、多個 `.v-select`、`.v-input__slot` 結構）。

## 身分驗證閘門

**沒有獨立的身分驗證頁面**。頁面頂部「檢舉人資料」區塊（身分證/居留證、姓名、聯絡電話、聯絡電話分機、地址、電子信箱）與下方「違規時間/車號/地點/事實」欄位在同一張表單上同時可見、可填，沒有先填一部分才「解鎖」看到另一部分的情形。送出案件按鈕 (`送出案件`) 預設為 `disabled`，推測是靠前端表單驗證（必填欄位、格式）解鎖，而非身分驗證流程。

> 因安全鐵律要求，未在「檢舉人資料」任何欄位填入任何文字（包含假資料），僅檢視 DOM 結構。

## 逐欄調查

### date
- 邏輯對應：違規日期
- DOM 元素種類：**plain**（一般文字輸入框）。`<input id="input-84" type="text" maxlength="7">`，父層 `.v-input` class 含 `v-text-field--outlined`，label 文字為「違規日期」。
- 格式細節：`maxlength="7"`，對應民國年 7 碼格式（例如 `1150824` = 民國115年08月24日），為**純數字直接輸入**，非西元年。
- 是否有日期選擇器 widget：欄位旁有一個 `mdi-calendar` 圖示（`<i class="v-icon ... mdi-calendar">`），但實際點擊該圖示後，DOM 中並未出現任何 `.v-menu__content` / `.v-picker` / `.v-date-picker-table` 彈窗（`document.querySelectorAll('.v-menu__content, .v-picker, .v-date-picker-table')` 回傳 0 筆），推測此圖示僅為裝飾用途，**沒有實際可互動的日期選擇彈窗**，仍須直接輸入 7 碼數字。
- 連動欄位：無。

### time
- 邏輯對應：違規時間
- DOM 元素種類：**plain**（一般文字輸入框，非下拉選單）。`<input id="input-90" type="text" maxlength="4" role="button">`，label 文字「違規時間(24小時制，如：1200、2330)」。
- 格式細節：與日期分開填寫，單一欄位，maxlength 4，直接輸入 24 小時制 4 碼數字（時分合併，如 `1630`），**不是時/分兩個獨立下拉選單**。
- 補充：此 input 帶有 `role="button"` 且無障礙樹顯示 `expandable haspopup="menu"`，點擊後確實會開出一個 `.v-menu__content`（id 對應 `aria-owns`），但該選單容器內 `role="option"`/子節點數為 0（空的）。判斷這是 Vuetify 文字欄位搭配的驗證提示/hint 彈出容器（平時無內容），並非真正的時間選擇清單，仍以直接輸入數字為主要填寫方式。
- 連動欄位：無。

### plate
- 邏輯對應：違規車號
- DOM 元素種類：**custom + plain 組合**。
  - 車種前綴：`custom` 下拉（Vuetify `v-select`），觸發元素 `.v-input__slot[aria-owns="list-94"]`，實際輸入框 `<input id="input-94" type="text" readonly aria-label="違規車號-車牌1">`... 標籤為「違規車號-車種」。開啟後選項為：`一般`、`機械`、`臨時`、`試車`、`領`、`外`、`使`（共 7 項），預設值為「一般」。
  - 車牌號碼本體：兩個 **plain** 文字框，中間以「－」符號視覺分隔：`<input id="input-97" aria-label="違規車號-車牌1" maxlength="4">` 與 `<input id="input-100" aria-label="違規車號-車牌2" maxlength="4">`。
- 連動欄位：無（車種預設已選「一般」，不影響車牌欄位是否顯示）。

### location
- 邏輯對應：違規地點
- **不是單一字串輸入框，而是拆成多個具名子欄位**，對照 schema 的 role 分類如下：
  - `district`（行政區）：**custom** 下拉，`.v-input__slot[aria-owns="list-103"]`，底層 `<input id="input-103" readonly aria-label="違規地點-行政區">`。開啟後為臺中市行政區清單（實測看到 20 筆：中區、東區、南區、西區、北區、北屯區、西屯區、南屯區、太平區、大里區、霧峰區、烏日區、豐原區、后里區、石岡區、東勢區、和平區、新社區、潭子區…，含捲動載入，非全部一次渲染）。
  - `road`（路段）：**custom** 下拉（combobox 樣式），底層 `<input id="input-106" aria-label="違規地點-路段">`。**未選擇行政區前為 `disabled`，value 顯示「請先選擇行政區」**；選擇行政區（實測選「北區」）後立即變為可互動，選項清單為「行政區+路名」組合的真實清單（例如「北區一中街」「北區力行路」「北區三民路三段」…），屬**受控詞彙**而非自由輸入，可視為 road 欄位有結構化清單、可靠對應到 road role。
  - 其餘結構化片段（皆為 **plain** 文字輸入框，且皆有各自的 maxlength）：
    - 「違規地點-公里」`input-109`（KM）
    - 「違規地點-巷」`input-112`
    - 「違規地點-弄」`input-115`
    - 「違規地點-號」`input-118`
    - 「違規地點-之」`input-121`
  - 交叉路口區塊（若違規發生在路口，改填這組）：「交叉路口-路段」`input-124`（custom combobox）、「交叉路口-巷」`input-127`、「交叉路口-弄」`input-130`（皆為 plain），**同樣預設 disabled，需先選好行政區才會一起解鎖**（實測：選擇行政區後，`地點-路段`、`交叉路口-路段`、`交叉路口-巷`、`交叉路口-弄` 四者同時從 disabled 變為可互動）。
  - `remainder`（其餘/無法可靠拆分）：「地點備註」`input-133`（plain textbox，maxlength 50）。頁面上明確說明此欄位用途：「選擇區域及路段後，若無法於上述欄位填寫詳細地址(巷、弄、號、KM等)，請於此欄位填寫說明(如匝道口、隧道東往西出口、高架橋南往北方向等)」——這正是 schema 中「語意上無法可靠拆分」的片段，應標記為 remainder，**不建議程式硬拆**。
- 連動欄位：**是**。行政區（district）未選擇前，路段（road，含一般地點與交叉路口兩組）皆為 disabled 狀態，文字提示「請先選擇行政區」；選定行政區後才會一起啟用。此為明確的欄位連動案例。

### description
- 邏輯對應：違規事實說明
- DOM 元素種類：**plain**。`<textarea maxlength="200" aria-label="違規事實說明">`，多行文字框。
- 連動欄位：無。
- 補充：此區塊上方另有一個 checkbox「我確認所提供資料包含清晰車牌。」，屬於同一區塊但非 description 欄位本身。

### violation
- 邏輯對應：違規事實
- DOM 元素種類：**custom** 下拉。觸發元素 `.v-input__slot[aria-owns="list-136"]`，底層 `<input id="input-136" readonly aria-label="違規事實">`，label「請選擇違規事實」。
- 連動欄位：無（不需要先填其他欄位才會出現，本身在頁面載入時即可直接開啟）。
- 格式細節：清單為捲動載入（實測看到 20 筆，含「請選擇違規事實」佔位項），內容格式為「條-項-款 具體條文文字」，例如：
  - `30-1-2所載貨物滲漏、飛散、脫落、掉落或氣味惡臭。`
  - `31-6機車駕駛人或附載座人未依規定戴安全帽者。`
  - `31之1-1(汽車)以手持方式使用行動電話…或…`
  - `[快速公路]33-1-2未保持安全距離。`
  - `42 汽車駕駛人，不依規定使用燈光者。`
  - `43-1-1在道路上蛇行，或以其他危險方式駕車。`

  文字具體到「條文號碼＋簡短違規行為描述」，**足夠具體可供程式做關鍵字/模糊比對**（例如比對「安全帽」「手持…行動電話」「蛇行」等關鍵詞）。

### evidenceImages
- 邏輯對應：檔案上傳
- DOM 元素種類：**file-trigger**。頁面上可見觸發按鈕「加入檔案」(`<button>加入檔案</button>`)，實際 `<input type="file" multiple accept=".jpg,.jpeg,.png,.bmp,.tiff,.mp4,.mov,.wmv,.avi,.3gp">` 已存在於 DOM 中（`style.display: none`，`offsetParent === null`，位於 `.v-card__text` 內），推測「加入檔案」按鈕透過程式呼叫觸發此隱藏 input 的原生檔案選擇視窗。
- 關鍵屬性：`multiple="true"`，代表**單次即可一次選取多個檔案**（不是像新北市那樣逐一增量注入新槽位）。
- 上傳限制（頁面文字提示）：每案總容量 100MB，至多可上傳 5 個檔案；支援類型為圖片 jpeg/png/bmp/tiff 與影片 mov/wmv/avi/mp4/3gp。
- 上傳成功後會顯示一個表格，欄位為：#（序號）、縮圖、拍攝日期、大小(MB)、操作。
- 連動欄位：無（此按鈕與 input 一開始就可見可操作，不需要先填其他欄位才出現）。

## 附件上傳機制

單一隱藏 `<input type="file" multiple>` + 可見的「加入檔案」觸發按鈕（**file-trigger** 模式），支援單次多選（`multiple`），非台北市的彈窗選檔模式、也非新北市逐槽注入模式。上傳後在表格列出縮圖與拍攝日期／大小，並提供「操作」欄位（未展開檢視，推測是刪除/預覽功能，因未實際上傳檔案故未進一步驗證其行為）。

## 檢舉條文內容

`violation` 欄位選項內容為「條文號碼（含項/款）＋具體違規行為文字敘述」，格式一致、文字具體，包含明確關鍵詞（如「安全帽」「行動電話」「蛇行」「未保持安全距離」等），**足夠支撐程式端做關鍵字比對或模糊比對**，不需仰賴使用者自行輸入條文號碼。清單另外標示 `[快速公路]` 前綴區分快速公路專屬條款。清單為虛擬捲動載入，實際完整項目數未逐一列出（僅取樣前 20 筆），如需完整清單建議之後另行以捲動或 API 方式驗證。

## 無法確定 / 需要人工複核的項目

1. **日期欄位的行事曆圖示是否真的完全無作用**：本次測試點擊圖示後未觀察到任何 `.v-menu__content`/`.v-picker` 元素出現，但無法排除是否需要特定互動序列（例如先聚焦輸入框、或圖示的事件繫結在更外層容器）才能觸發，目前結論為「圖示存在但未觀察到可用彈窗」，建議之後如有機會可另行確認。
2. **時間欄位彈出的空白 `.v-menu__content`**：實際用途不明（未見任何 `option`/子節點），推測是 Vuetify 表單驗證提示容器而非真正的時間選單，但未能百分之百排除是否在特定條件（例如輸入不合法格式後）才會顯示內容。
3. **交叉路口欄位與「一般地點」欄位是否互斥**：頁面上同時存在「違規地點」與「交叉路口」兩組欄位，兩者均在選擇行政區後解鎖，但未實測「同時填寫兩組」或「只能擇一填寫」時後端/前端是否有额外檢查（例如二選一的驗證邏輯），需要人工複核。
4. **檔案上傳「操作」欄位的實際功能、以及觸發「加入檔案」按鈕後是否還有其他中介步驟（如彈出確認視窗）**：因為要真正觸發原生檔案選擇對話框、涉及作業系統層級 UI，無法在本次唯讀式 DOM 檢視中安全驗證，故未實際點擊「加入檔案」按鈕。
5. **行政區清單與路段清單的完整項目數**：兩者皆為虛擬捲動清單，本次僅取樣清單前 20 筆，未逐一捲動列出全部臺中市行政區（實際應有 29 區）與各區完整路名清單。
6. **地點備註（remainder）是否真的完全無法程式化拆分**：目前僅依頁面文字提示（"若無法於上述欄位填寫詳細地址...請於此欄位填寫說明"）判斷為 remainder，實務上可能仍有一部分內容具備可辨識樣式（如"XX交流道匝道口"），是否要嘗試更細緻的規則拆分需要人工複核。
